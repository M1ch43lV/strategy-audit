# Plan: re-measuring the strategy-audit corpus

> **Status: historical working plan (2026-08).** This document records the
> original corpus-repair workflow and is retained for provenance. Its counts,
> phase status, and Class 1/Class 2 boundary are not current. Current repair
> facts belong in `repair/REGISTER.md`; the active regime methodology is
> `REGIME_AUDIT_PLAN.md`.

Working document. Status as of 2026-08-25.

---

## 1. The question

`github.com/Apex-prim/strategy-audit` measured 496 of 895 public freqtrade
strategies and concluded that none beats buy-and-hold. 399 (44.6%) never
produced a number and were reported under one label, `G0_measured`.

**The question this work answers:** is that 44.6% a finding about *strategy
quality* — the audit's implicit reading — or about *friction between old
community code and a modern runtime*?

The audit author's own `loadcheck_run.json` already points at the answer: of
362 strategies probed, **268 import cleanly**. They are not broken code. They
die at run time, mostly on conditions the test rig sets rather than the
strategy.

Secondary goal: cluster the corpus so strategies can be evaluated **per market
phase** instead of averaged across one fixed window, where opposing patterns
cancel each other out.

---

## 2. The rule that governs everything else

Two classes of repair. The distinction decides whether a result can be compared
with the published ledger at all.

| | Class 1 | Class 2 |
|---|---|---|
| What changes | the environment | the strategy file |
| Example | `pip install finta`, `PYTHONPATH`, `np.NAN` alias | `fillna(method=)` to `ffill()` |
| What is measured | the published code | our edit of it |
| Reporting | comparable with the audit's ledger | separate stratum, always flagged |

Class 1 is **not** "neutral" — installing a package changes the conditions too.
The honest phrasing is *faithful to the original within the given runtime
stack*, which is why `ftenv` runs the audit's exact stack: freqtrade 2026.7,
pandas 3.0.5, numpy 2.5.2, TA-Lib 0.7.1.

**The line inside Class 1 is alias vs. reimplementation.** `np.NAN = np.nan` is
an alias — allowed. `technical.indicators.accumulation_distribution` was removed
with no replacement; writing our own and giving it the original's name would be
an invention wearing the original's label — refused, and the 2 strategies that
need it stay unmeasured.

A borderline case treated as its own stratum: running the 36 short-capable
strategies in futures mode is technically Class 1, but leverage and funding make
those numbers incomparable with spot. They do not belong in the same table.

## 3. Phases

### Done — Phase 0: isolated environment

`strategy-audit/ftenv`, freqtrade 2026.7. Separate from the user's working
`.venv` because `pmdarima` and `scikit-optimize` can pull numpy backwards.
`harness.py` expects this exact path and was not finding it.

### Done — Phase 1a: missing dependencies

`finta arrow ta ephem pywavelets py3cw scikit-optimize feature_engine
statsmodels optuna tensorflow lightgbm pmdarima talipp xgboost portalocker
catboost matplotlib`. Stack verified unchanged after every step.

Not installed: `zigzag` — pins `Cython<0.30`, whose DLL is blocked by a Windows
application control policy on this machine. Its `pyproject.toml` is also
malformed. 5 strategies stay unmeasurable.

### Done — Phase 1b: module search path

`repair/modpath.py`. Helper modules that are in the corpus but invisible because
`harness.py` passes `--strategy-path <dirname(file)>`. Lookup restricted to the
strategy's own repository. **8 strategies resolved** — the 22 estimated
beforehand were too optimistic.

### Done — Phase 1c: compatibility shim

`repair/compat_shim.py` via `sitecustomize.py`, so it also covers the
subprocesses freqtrade spawns. Restores `np.NAN`/`NaN`/`INF`/`float_`,
`numpy.lib.math`, and the parameter classes that moved from
`freqtrade.strategy.hyper` to `freqtrade.strategy.parameters`. All aliases to
identical objects.

### Done — Phase 1d: eight corpus files recovered

5 from `ShahAnuj2610/my-freqtrade`, whose working tree was empty because the
checkout failed on colons in filenames — recovered from the git object store.
3 from `PeetCrypto/freqtrade-stuff` with spaces and parentheses in their names —
re-fetched with URL encoding. All 8 verified to parse and contain the expected
`IStrategy` class. Classification now covers 895 of 895.

### Done — Phase 1e: candle data

`repair/fetch_parallel.py` reuses the audit's `fetch_bulk.py` data logic
unmodified and replaces only the scheduling: 16 concurrent (pair, timeframe)
jobs. 88 files, 8 pairs x 11 timeframes, 54.8M candles, 1.4 GB, zero corrupt
files, no network failures across 75 jobs.

### Done — Phase 1f: clustering

`cluster/classify.py` on five independent axes with the reason for every label
recorded, so a misclassification is refutable case by case.

### Done — Phase 1g: translation

`repair/i18n.py`. All 37 Russian string literals in `harness.py` extracted by AST
walk and covered, verified by re-scanning translated output for Cyrillic.
Translation runs **after** measurement; every field keeps its original under a
`_ru` suffix.

### Running — Phase 2: Class 1 measurement

`repair/run_class1.py` over 283 strategies, 8 processes. Uses the audit's own
`harness.audit_one` unchanged, from a pristine `origin/main` copy in
`repair/audit_clean/`, with the author's original config: 8 pairs,
`max_open_trades: 3`, `stake_amount: unlimited`, spot, fee 0.1% per side, windows
2018-03-01..2020-03-01 and 2020-03-01..2026-08-20.

Cards go to `repair/results_class1/`, tagged `source="class1_rerun"` and
`run_class="class1"`. The audit's own 896 cards are never overwritten — the two
runs have to stay comparable.

### Next — Phase 3: mechanical pandas patches (Class 2)

**Nothing here has been done yet, and that is deliberate.** Phase 3 waits for
Phase 2 to finish, because only the run tells us *which* strategies actually
need a patch. The static scan finds 24 candidates — `fillna(method=)` 18,
`pd.to_datetime(unit=)` on strings 4, `np.float` 1, `sum(level=)` 1 — while the
rest of the 68 pandas breaks surface only at run time. Patching before that
would mean writing into somebody else's code on suspicion.

**Current state, verified rather than asserted:** exactly 8 strategy files have
been written during this work, and they are exactly the 8 that were *missing*
(Phase 1d). All 8 are byte-identical to their source by SHA-256, checked against
the git object store and against `raw.githubusercontent.com`. No pre-existing
strategy file carries a new mtime. The corpus has been completed, not altered.

Rules for when it does happen:

- **Originals stay untouched.** Patches live in an overlay copy with a readable
  diff per file, so every change is reviewable and reversible on its own.
- **Only mechanical, meaning-preserving migrations.** `df.fillna(method='ffill')`
  to `df.ffill()` is the same operation under a new name. Anything whose
  behaviour could shift is left alone.
- **Own stratum.** Cards get `run_class="class2"` and never share a column with
  Class 1 results. Otherwise exactly the contamination the split exists to
  prevent leaks back in.
- **Stop criteria.** Do not touch a strategy when the repair would take more
  than roughly 15 minutes, when the effect of the change is not obvious, or when
  it amounts to porting rather than repair. The 25 freqtrade API breaks
  (`min_roi_reached_entry` signature and friends) fall under the last one and
  stay unfixed.
- **The Class 1 boundary applies here too:** an alias is allowed, a
  reimplementation is not. A patch that rewrites what an indicator computes is
  no longer measuring the published strategy.

### Later — Phase 4: regime analysis

Cut results by market phase using the cluster labels and their stated
`regime_hypothesis`. This is the part the original audit does not do, and the
reason the clustering exists.

**Why `repair/audit_clean/` exists:** the working tree's `.py` files had their
Russian comments and string constants overwritten with `X` by an unrelated tool.
That collapsed `НЕ ПРИМЕНИМА` ("not applicable") and `НЕ ЗАПУСКАЛИ` ("not run")
into the same string `"XX XXXXXXXXX"` — two distinct states became
indistinguishable. Measuring against that copy would have silently corrupted
every card, so the harness is imported from `origin/main` instead.

## 7. Errors of ours, found and fixed

Recorded because a contribution that hides its own mistakes is asking for trust
it has not earned.

1. **`sys.path` order.** `loadprobe.py` prepended the strategy directory, so
   local files such as `technical.py` shadowed real packages and **12 strategies
   that had loaded fine started failing**. Caught only because the result (287)
   was worse than the author's baseline (268 of 362) and the number was not
   taken at face value. Fixed to append.
2. **Verdict read from the last output line.** TensorFlow writes to stderr after
   the probe prints, so two results were reported as `I0000 ...` log lines. Fixed
   with an explicit sentinel.
3. **The fix for (2) broke the probe to 0 of 399.** Of two intended
   replacements only the parser-side one applied, and the guarding assertion
   merely checked the marker appeared *somewhere in the file* — which that alone
   satisfied. A check that cannot see its own failure is not a check. The
   assertion now looks inside the `CHILD` block specifically.
4. **Wrong working directory.** freqtrade resolves `user_data` relative to the
   CWD and `harness.py` passes no `--datadir`. The first test run reported "No
   data found" for a strategy whose data was present — our fault, presented as
   the strategy's.
5. **Estimate of 22 for Phase 1b.** The real number is 8. 38 strategies import a
   helper module that does not exist in their own repository at all.
6. **Three wrong diagnoses of a "hang", and two destroyed measurement runs.**
   The Phase 2 run was killed twice on the belief that its processes were stuck.
   They were not. `AdaptiveMAStrategy` was later timed end to end: **4 min 24 s**
   for the in-sample window alone, producing a real result (3195 trades,
   -93.63%, market change -58.48%). Nothing had ever hung.

   The diagnoses were, in order: processes stuck (no), too much parallelism (no),
   our own `compat_shim` deadlocking freqtrade (disproved by an A/B test). All
   three rested on `Get-Process.CPU` reporting 0, **an instrument that was never
   validated**. The attempt to validate it against a deliberately CPU-burning
   process came too late — that control had already finished.

   Cost: two aborted runs and one fabricated card (`BbandRsi`, carrying exit
   code 4294967295 — our own kill recorded as a property of the strategy). The
   card was deleted and `measure_one.py` now refuses to write a card for any
   known kill exit code.

   The lesson is the same one this project levels at the audit elsewhere: a
   number that has not been checked is not evidence. Progress is now judged from
   the driver's start-lines and card timestamps, which actually measure
   progress, and not from a process counter nobody verified.

   **Consequence for method:** `audit_one` makes four freqtrade calls per
   strategy (in-sample, out-of-sample, lookahead, recursive). A heavy 5m strategy
   costs 30-60 minutes. Sequential execution over 266 strategies would take days,
   so the run is parallel by necessity, not by preference.

## 8. Findings that argue against our own thesis

Kept deliberately, because only reporting the supporting half would make the
rest untrustworthy.

- **38 strategies were copied between repositories without their helper
  module.** `CryptoFrog` sits in `PeetCrypto_freqtrade-stuff` while its
  `custom_indicators.py` exists only in `froggleston_cryptofrog-strategies`.
  They were never runnable where they are published. That is a real publication
  defect and it supports the audit author's copy thesis.
- **A large part of the Class 1 gain is data, not code.** Before the candle
  download only 28 of the 353 importing strategies were testable. Much of the
  44.6% was never a claim about strategy quality *or* about library drift — it
  was simply an incomplete local dataset.

## 10. Data note

The 1w series are missing 8 weeks each, identically across all pairs, and every
missing week starts in the last days of a month. Binance's monthly archive omits
weeks that straddle a month boundary — a property of the source and of
`fetch_bulk.py`, not of the parallel driver. Exactly 1 strategy declares `1w`.
Recorded rather than fixed, because an undocumented hole in a series is the kind
of thing that later gets mistaken for a result.
